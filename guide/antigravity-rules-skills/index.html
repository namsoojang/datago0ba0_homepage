실무 가이드

반복 지시를 줄이고, 팀의 기준과 업무 절차를 재사용하는 가장 실용적인 방법

공식 문서 검증 2026.07.18 · 기획·검수 데이터공방 장남수

R/S

Rule은 에이전트가 계속 지켜야 할 기준이고, Skill은 특정 업무를 수행하는 재사용 가능한 절차입니다.

중요: Rule과 Skill은 정확성을 보증하지 않습니다. 중요한 수치, 파일 변경, 명령 실행 결과는 사람이 검토하고 테스트해야 합니다.

130초 선택법

KEEP THE STANDARD

Rule

문체, 보안 정책, 수정 금지 영역, 필수 검증처럼 계속 지켜야 할 기준

REUSE THE PROCESS

Skill

데이터 정제, 보고서 생성, 배포 점검처럼 특정 작업에서 재사용할 절차

판단 질문선택
모든 작업에서 계속 지켜야 하는가?Rule
특정 업무를 시작할 때만 필요한가?Skill
파일 종류나 경로에 따라 적용하는가?Glob Rule
지침·스크립트·템플릿을 함께 재사용하는가?Skill

“고객 개인정보는 항상 마스킹한다”는 Rule이고, “매월 CSV를 정제해 보고서를 만든다”는 Skill입니다.

2Rules: 계속 지켜야 할 업무 기준

Rules는 코딩 스타일, 수정 금지 영역, 보안 기준, 필수 검증 명령처럼 프로젝트 전반에 반복 적용할 제약을 정의합니다.

공식 저장 위치

프로젝트/.agents/rules/
├── security.md
├── report-format.md
└── data-quality.md

전역 Rule: ~/.gemini/GEMINI.md

이전 .agent/rules/도 하위 호환되지만 새 문서는 .agents/rules/를 권장합니다. Rule은 Markdown이며 파일당 12,000자 제한을 고려합니다.

활성화 방식

방식언제 쓰나예시
Manual필요할 때 직접 선택특정 보고서 서식
Always On모든 작업비밀키 커밋 금지
Model Decision설명을 보고 모델이 판단데이터 분석 규칙
Glob파일 경로·확장자에 따라data/**/*.csv

좋은 Rule 예시

# 데이터 품질 규칙

- 원본 파일을 덮어쓰지 않는다.
- 고객 이름, 전화번호, 이메일은 마스킹한다.
- 결측치 처리 전 열별 결측률을 보고한다.
- 완료 후 입력 행 수와 출력 행 수를 비교한다.
- 수행할 수 없는 규칙은 이유를 알린다.

“깔끔하게 작성” 같은 추상 표현보다 대상·행동·검증 기준을 분명히 적습니다.

3Skills: 반복 가능한 업무 절차

Skill은 특정 작업을 수행하는 지침, 모범 사례, 선택적 스크립트와 참고자료를 묶은 폴더형 패키지입니다. Python 파일 하나가 Skill인 것은 아닙니다. 최소 구성요소는 YAML frontmatter가 포함된 SKILL.md입니다.

공식 저장 구조

.agents/skills/
└── monthly-report/
    ├── SKILL.md
    ├── scripts/       # 선택: 반복 실행 코드
    ├── references/    # 선택: 규격·업무 지식
    └── assets/        # 선택: 템플릿·이미지

워크스페이스 Skill은 .agents/skills/<name>/, 전역 Skill은 ~/.gemini/config/skills/<name>/에 둡니다.

SKILL.md 최소 예시

---
name: monthly-report
description: 월간 CSV를 정제하고 품질을 검사한 뒤
  요약 보고서를 만듭니다.
---

# Monthly Report

## 실행 절차
1. 입력 파일과 출력 위치를 확인한다.
2. 원본을 보존하고 복사본으로 작업한다.
3. scripts/clean_data.py를 실행한다.
4. 입력·출력 행 수와 결측률을 검증한다.
5. 결과 파일과 남은 위험을 요약한다.

Skill 설명은 발견과 활성화의 핵심입니다. “데이터 작업을 도움”보다 “CSV 중복 제거·날짜 표준화·결측률 검증에 사용”처럼 구체적으로 작성합니다.

월간 고객 보고서라면 Rule이 개인정보 마스킹·원본 보존·검증 기준을 맡고, Skill이 파일 확인 → 정제 → 품질 검사 → 보고서 생성 순서를 맡습니다.

추천 요청문

monthly-report Skill을 사용해 이번 달 고객 데이터를 정리해줘.
원본은 수정하지 말고, 실행 전에 입력 파일과 출력 위치를 알려줘.
완료 후 입력·출력 행 수와 결측률 변화를 표로 보여줘.

5토큰과 비용에 대한 정확한 설명

Skill은 긴 절차를 매번 붙여 넣거나 코드를 반복 생성하는 낭비를 줄일 수 있지만 “90% 절감” 같은 고정 비율을 보장하지 않습니다.

  • Skill의 이름과 설명은 발견을 위해 컨텍스트에 노출될 수 있습니다.
  • 관련 Skill이 활성화되면 SKILL.md 전체 지침을 읽습니다.
  • 스크립트 재사용은 동일 로직을 매번 생성하는 비용과 변동을 줄입니다.
  • 실제 사용량은 모델, 대화 길이, Skill 크기와 실행 결과에 따라 달라집니다.
핵심 가치: 고정된 절감률보다 반복 업무의 표준화, 점진적 공개, 검증 절차 재사용에 있습니다.

6안전하게 운영하는 체크리스트

작성할 때

  • 한 가지 목적에 집중
  • 적용·제외 시점 명시
  • 파괴적 작업 조건 명시
  • 입력과 출력 검증
  • 비밀값을 예제에서 제외

실행할 때

  • 현재 폴더와 대상 확인
  • 명령의 영향 검토
  • 승인 절차를 우회하지 않기
  • 민감정보 노출 확인
  • 테스트 결과 기록

유지보수할 때

  • 공식 문서 정기 점검
  • 실패 사례 반영
  • 중복 지침 정리
  • 스크립트 버전 점검
  • 변경일과 담당자 기록

7자주 하는 실수

스크립트 하나를 Skill이라고 부르기언제 사용하고 어떻게 검증할지 정의한 SKILL.md가 필요합니다.
모든 지침을 Always On Rule에 넣기지속 기준만 Rule에 두고 특정 업무 절차는 Skill로 분리합니다.
“무조건 자동 실행”을 요구하기삭제·외부 전송·설치는 승인과 대상 확인을 우선합니다.
Rule이 결과를 100% 보장한다고 생각하기중요한 결과는 테스트, diff, 원본 대조로 검증합니다.

STEP 03 · 우리 팀 업무에 적용하기

공통 Rule, 반복 업무 Skill, 검증·승인 절차를 현재 조직의 데이터 업무와 교육 대상에 맞게 설계할 수 있습니다.

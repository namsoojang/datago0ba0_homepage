# Antigravity Rules & Skills 실무 가이드

부제: 반복 지시를 줄이고, 팀의 기준과 업무 절차를 재사용하는 방법

검증일: 2026-07-18  
기획·검수: 데이터공방 장남수 · [datagongbang.kr](https://datagongbang.kr)

Antigravity에서 **Rule은 에이전트가 계속 지켜야 할 기준**이고, **Skill은 특정 업무를 수행하는 재사용 가능한 절차**입니다. 둘을 구분해 설계하면 긴 지시를 매번 다시 쓰지 않아도 되고, 결과물의 일관성과 검증 가능성을 높일 수 있습니다.

> Rule과 Skill은 결과의 정확성을 보증하는 장치가 아닙니다. 중요한 수치·파일 변경·명령 실행 결과는 사람이 검토하고 테스트해야 합니다.

---

## 1. 30초 선택법

| 질문 | 선택 |
|---|---|
| 모든 작업에서 계속 지켜야 하는가? | **Rule** |
| 특정 업무를 시작할 때만 필요한 절차인가? | **Skill** |
| 파일 종류나 경로에 따라 적용해야 하는가? | **Glob Rule** |
| 지침과 스크립트·템플릿을 함께 재사용해야 하는가? | **Skill** |

예를 들어 “고객 개인정보는 항상 마스킹한다”는 Rule이고, “매월 CSV를 정제해 보고서를 만든다”는 Skill입니다.

## 2. Rules: 계속 지켜야 할 업무 기준

Rules는 코딩 스타일, 수정 금지 영역, 보안 기준, 필수 검증 명령처럼 프로젝트 전반에서 반복 적용할 제약을 정의합니다.

### 공식 저장 위치

```text
프로젝트/.agents/rules/
├── security.md
├── report-format.md
└── data-quality.md
```

- 워크스페이스 Rule: `<workspace>/.agents/rules/`
- 전역 Rule: `~/.gemini/GEMINI.md`
- 이전 `.agent/rules/` 경로도 하위 호환되지만 새 문서는 `.agents/rules/`를 권장합니다.
- Rule 파일은 Markdown이며 파일당 12,000자 제한을 고려합니다.

### 활성화 방식

| 방식 | 적합한 상황 | 예시 |
|---|---|---|
| Manual | 사용자가 필요할 때 직접 선택 | 특정 보고서 서식 |
| Always On | 모든 작업에 항상 적용 | 비밀키 커밋 금지 |
| Model Decision | 설명을 보고 모델이 판단 | 데이터 분석 작업 규칙 |
| Glob | 파일 경로·확장자에 따라 적용 | `data/**/*.csv`, `src/**/*.ts` |

Manual Rule은 Agent 입력창에서 `@`로 지정할 수 있습니다. 일반 참고문서도 `@파일경로`로 참조할 수 있지만, 단순 첨부 문서와 공식 Rule은 적용 범위와 활성화 방식이 다릅니다.

### 좋은 Rule 예시

```markdown
# 데이터 품질 규칙

- 원본 파일을 덮어쓰지 않는다.
- 고객 이름, 전화번호, 이메일은 결과 예시에서 마스킹한다.
- 결측치 처리 전 열별 결측률을 보고한다.
- 분석 완료 후 입력 행 수와 출력 행 수를 비교한다.
- 수행할 수 없는 규칙이 있으면 임의로 생략하지 말고 이유를 알린다.
```

좋은 Rule은 “깔끔하게 작성해줘” 같은 추상 표현보다 **대상·행동·검증 기준**이 분명합니다.

## 3. Skills: 반복 가능한 업무 절차

Skill은 특정 작업을 수행하기 위한 지침, 모범 사례, 선택적 스크립트와 참고자료를 묶은 폴더형 패키지입니다. Python 파일 하나를 Skill이라고 부르지는 않습니다. 최소 구성요소는 YAML frontmatter가 포함된 `SKILL.md`입니다.

### 공식 저장 구조

```text
.agents/skills/
└── monthly-report/
    ├── SKILL.md
    ├── scripts/       # 선택: 반복 실행 코드
    ├── references/    # 선택: 규격·업무 지식
    └── assets/        # 선택: 템플릿·이미지
```

- 워크스페이스 Skill: `<workspace>/.agents/skills/<skill-name>/`
- 전역 Skill: `~/.gemini/config/skills/<skill-name>/`
- Antigravity는 대화 시작 시 Skill의 이름과 설명을 확인하고, 관련 작업에서 전체 지침을 읽는 점진적 공개 방식을 사용합니다.

### SKILL.md 최소 예시

```markdown
---
name: monthly-report
description: 월간 CSV를 정제하고 품질을 검사한 뒤 요약 보고서를 만듭니다.
---

# Monthly Report

## 사용 시점
- 월간 매출 또는 고객 CSV 보고서를 만들 때

## 실행 절차
1. 입력 파일과 출력 위치를 확인한다.
2. 원본을 보존하고 복사본으로 작업한다.
3. scripts/clean_data.py를 실행한다.
4. 입력·출력 행 수와 결측률을 검증한다.
5. 결과 파일, 검증 결과, 남은 위험을 요약한다.
```

Skill 설명은 에이전트가 사용 여부를 판단하는 핵심 정보입니다. “데이터 작업을 도움”보다 “CSV 중복 제거·날짜 표준화·결측률 검증에 사용”처럼 구체적으로 작성합니다.

## 4. Rule과 Skill을 함께 쓰는 실무 패턴

월간 고객 보고서를 예로 들면 다음처럼 역할을 분리할 수 있습니다.

1. **Rule**이 개인정보 마스킹, 원본 보존, 결과 검증 기준을 강제합니다.
2. **Skill**이 파일 확인 → 정제 스크립트 실행 → 품질 검사 → 보고서 생성 순서를 안내합니다.
3. 에이전트가 실행할 명령과 변경 파일을 제시합니다.
4. 사용자가 권한과 대상을 확인한 뒤 승인합니다.
5. 에이전트가 결과를 검증하고 남은 위험을 보고합니다.

추천 요청문:

```text
monthly-report Skill을 사용해 이번 달 고객 데이터를 정리해줘.
원본은 수정하지 말고, 실행 전에 입력 파일과 출력 위치를 먼저 알려줘.
완료 후 입력·출력 행 수와 결측률 변화를 표로 보여줘.
```

## 5. 토큰과 비용에 대한 정확한 설명

Skill은 긴 절차를 매번 프롬프트에 붙여 넣거나 코드를 반복 생성하는 낭비를 줄일 수 있습니다. 그러나 “90% 절감”처럼 고정된 절감률을 보장하지는 않습니다.

- Skill의 이름과 설명은 발견을 위해 컨텍스트에 노출될 수 있습니다.
- 관련 Skill이 활성화되면 `SKILL.md`의 전체 지침을 읽습니다.
- 스크립트를 재사용하면 동일 로직을 매번 생성하는 비용과 변동을 줄일 수 있습니다.
- 실제 사용량은 모델, 대화 길이, Skill 크기, 실행 결과에 따라 달라집니다.

핵심 가치는 단순한 토큰 절감보다 **반복 업무의 표준화, 점진적 공개, 검증 절차 재사용**에 있습니다.

## 6. 안전하게 운영하는 체크리스트

### 작성할 때

- [ ] Rule과 Skill이 한 가지 목적에 집중한다.
- [ ] 적용 시점과 적용하지 않을 시점을 적었다.
- [ ] 파괴적 명령, 외부 전송, 원본 덮어쓰기 조건을 명시했다.
- [ ] 스크립트 입력값과 출력 위치를 검증한다.
- [ ] 비밀키와 개인정보를 예제에 넣지 않았다.

### 실행할 때

- [ ] 실행 전 현재 폴더와 대상 파일을 확인한다.
- [ ] 에이전트가 제시한 명령의 영향을 읽는다.
- [ ] 환경의 권한 승인 절차를 우회하지 않는다.
- [ ] 결과 파일과 로그에 민감정보가 남지 않았는지 확인한다.
- [ ] 테스트 결과와 남은 위험을 기록한다.

### 유지보수할 때

- [ ] 공식 문서의 경로와 기능 변경을 정기 점검한다.
- [ ] 실패 사례를 Rule 또는 Skill의 검증 단계에 반영한다.
- [ ] 오래된 스크립트와 중복 지침을 정리한다.
- [ ] 변경일과 담당자를 기록한다.

## 7. 자주 하는 실수

### `modules/cleaner.py`만 만들고 Skill이라고 부르기

스크립트는 실행 코드일 뿐입니다. 언제 사용하고 어떤 순서로 검증할지를 정의한 `SKILL.md`와 함께 패키지로 구성해야 합니다.

### 모든 지침을 Always On Rule 하나에 넣기

컨텍스트가 불필요하게 커지고 규칙 간 충돌이 생길 수 있습니다. 지속 기준만 Rule에 두고, 특정 업무 절차는 Skill로 분리합니다.

### “무조건 자동 실행”을 요구하기

파일 삭제, 외부 전송, 패키지 설치 같은 작업은 환경 설정과 위험도에 따라 승인이 필요합니다. 자동화보다 대상 확인과 복구 가능성을 우선합니다.

### Rule이 결과를 100% 보장한다고 생각하기

Rule은 모델을 안내하는 제약입니다. 중요한 결과는 테스트·diff·원본 대조로 검증해야 합니다.

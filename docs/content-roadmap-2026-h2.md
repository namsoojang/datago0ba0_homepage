## 0. 전제 조건 — 이것부터 하고 시작한다

> **블로그 정적 경로 전환(U1)이 완료되기 전에는 신규 블로그 글을 쓰지 않는다.**
>
> 색인되지 않는 구조에 글을 쌓는 것은 노동의 낭비다. 도구·가이드는 자체 HTML 페이지라 영향이 없으므로 먼저 진행 가능하다.

착수 순서: `L1·L2 수정` → `U1 블로그 구조 전환` → `C1 제안서 제작` → `콘텐츠 생산 시작`

## 1. 세 축의 역할 분리

지금 무료도구·가이드·블로그는 셋 다 "만들어 뒀다" 수준에 머물러 있고, 퍼널상 역할이 정의되어 있지 않다. 아래와 같이 역할을 나눈다.

| 축 | 퍼널 위치 | 역할 | 성공 지표 |
|---|---|---|---|
| **무료도구 (RPA)** | 최상단 | **검색 키워드 진입점.** 실무 고통 = 검색어 | 도구 페이지 자연 유입 세션 |
| **가이드** | 중간 | **고관여 리드 자석.** 도입 검토 중인 담당자 포획 | PDF 다운로드 → 상담 CTA 클릭률 |
| **블로그** | 중간~하단 | **HRD 의사결정 지원.** 담당자가 검색하는 업무 질문에 답 | 글 → 문의 제출 기여 수 |

핵심 원리: **도구로 넓게 잡고, 가이드로 깊이 끌고, 블로그로 결정을 돕는다.**

---

## 2. 무료도구 확장 (분기당 2~3개)

### 선정 기준

1. **검색 수요가 있는 실무 고통** — 사람들이 실제로 검색하는 문제인가
2. **브라우저 내 처리 가능** — 업로드 없음 = "사내 보안 걱정 없음" 메시지 유지 (기존 도구의 핵심 차별점)
3. **교육 커리큘럼과 연결** — 도구의 고통이 교육 주제로 자연스럽게 이어지는가

### 백로그 (우선순위 순)

| # | 도구 | 근거 | 연결 커리큘럼 |
|---|---|---|---|
| 1 | **엑셀 여러 시트/파일 병합기** | 검색 수요 최상위. 거의 모든 사무직의 반복 고통 | Python 실무 자동화 RPA |
| 2 | **개인정보 마스킹 도구**<br>(주민번호·연락처·계좌) | 컴플라이언스 고통. 기존 CRM 점검기와 시너지, 상호 링크 가능 | Python 데이터 정제 |
| 3 | **PDF 표 → 엑셀 추출기** | 검색 수요 높음. 브라우저 내 처리 가능 | 업무 자동화 워크숍 |
| 4 | **날짜/숫자 형식 통일기** | 데이터 정제 교육의 도입부 그 자체 | 비즈니스 분석 & 시각화 |
| 5 | **근태·연차 계산기** | **HR 담당자 유입 = 타깃 적합도 최상.** 우리 구매 결정자가 직접 검색하는 도구 | 전 트랙 (담당자 접점) |

> 5번은 검색량이 1~3번보다 낮을 수 있으나, **들어오는 사람이 정확히 우리 구매 결정자**라는 점에서 전략적 가치가 가장 높다. 유입량이 아니라 유입 품질로 평가할 것.

### 도구 출시 시 필수 동반 작업

각 도구는 단독 출시하지 않는다. 아래 5종을 세트로 발행한다.

- [ ] 전용 랜딩 페이지 (기존 도구 페이지 구조 복제)
- [ ] `SoftwareApplication` JSON-LD
- [ ] 본문 하단 상담 CTA (`data-consult-source="<도구명>"`)
- [ ] 회사소개서/제안서 다운로드 링크
- [ ] **사용법 블로그 글 1편** — 도구 ↔ 글 상호 내부 링크

`sitemap.xml` 등재 및 GTM·GA4 스니펫 포함 여부를 배포 전 확인한다.

## 3. 가이드 확장 (분기당 1~2편)

### 기존 포맷 유지

Antigravity 가이드 2편이 만든 구조는 좋다. 이 포맷을 그대로 복제한다.

```
guide/index.html (허브)
   └ STEP 01 → STEP 02 → 팀 상담 CTA
       └ 각 STEP에 PDF 다운로드 (비게이팅)
```

**PDF 비게이팅 원칙은 유지한다.** 이메일을 요구하면 다운로드가 급감하고, 우리 전략은 "먼저 충분히 준다"에 기반한다. 대신 **다운로드 직후 소프트 상담 제안**을 붙인다.

### 백로그 (우선순위 순)

| # | 가이드 | 근거 | 연결 |
|---|---|---|---|
| 1 | **Claude Code / Cursor 업무 자동화 입문** | 바이브 코딩 워크숍 트랙과 직결. 검색 수요 상승 중 | AI & AX 트랙 |
| 2 | **사내 AI 도입 체크리스트 (보안·거버넌스 편)** | **가장 고관여.** HRD/기획 담당자 정조준. 도입 검토 단계의 담당자가 검색하는 주제 | 전 트랙 + 컨설팅 |
| 3 | **NotebookLM 실무 활용** | `ref-12`(SeSAC) 교육에서 이미 다룬 주제 — 자산 재활용 | AI Survival |
| 4 | **Gemini 업무 활용** | `ref-05`(영업 직무 특강) 내용 자산화 | AI & AX 트랙 |

> 3·4번은 **이미 강의한 내용의 자산화**다. 새로 만드는 게 아니라 이미 있는 것을 문서로 바꾸는 작업이므로 투입 대비 산출이 좋다.

> 2번은 유일하게 "도구 사용법"이 아니라 "의사결정 지원" 성격의 가이드다. 구매 결정자를 직접 겨냥하므로 전환 기여가 가장 클 것으로 예상된다.

## 4. 블로그 재편

### 4-A. 카테고리 재정의

| 카테고리 | 상태 | 방향 |
|---|---|---|
| **HRD 실무** | 🆕 신설 | **유입의 핵심.** 담당자가 실제 검색하는 질문에 답한다 |
| 교육칼럼 | 유지 | `ref-07`, `ref-09`가 좋은 예. 관점·전문성 증명 |
| 출강후기 | **비중 축소** | 신뢰 자산이지 유입 자산이 아님. 사례 페이지로 연결하는 역할로 재정의 |
| 개발일지 | 유지 (저빈도) | 제품 신뢰. `ref-10`처럼 검색 수요 있는 주제일 때만 |

### 4-B. "HRD 실무" 초기 백로그

담당자가 검색창에 실제로 칠 법한 질문에서 출발한다.

| # | 주제 | 검색 의도 | 연결 |
|---|---|---|---|
| 1 | **사내 AI 교육 커리큘럼 설계하는 법** | "사내 AI 교육 어떻게 짜지" | 커리큘럼 3트랙 |
| 2 | **AX 교육 예산·기간 잡는 기준** | "AI 교육 비용 얼마" — **가격 신호 부재(C1)를 콘텐츠로 우회** | 교육제안서 다운로드 |
| 3 | **교육 만족도 설문 문항 설계법** | "교육 만족도 설문 문항" | 만족도 분석기 도구 |
| 4 | **직급별·직무별 AI 교육 난이도 조정** | "임원 AI 교육 / 신입 AI 교육" | 커리큘럼 |
| 5 | **사내 보안 정책 하에서 AI 실습 진행하기** | "폐쇄망 AI 교육" — `ref-04`(이수페타시스) 경험 자산화 | FAQ 보안 항목 |

> 2번은 특히 중요하다. 사이트에 가격 신호가 전혀 없다는 것이 전환 병목인데(C1), **가격표를 만들지 않고도 "예산을 잡는 기준"을 콘텐츠로 제공**하면 담당자의 내부 품의를 도우면서 제안서 다운로드로 자연스럽게 연결된다.

### 4-C. 발행 리듬

**월 2편** — HRD 실무 1편 + (후기 또는 칼럼) 1편.

무리한 목표를 세우지 않는다. 중요한 건 빈도가 아니라 **HRD 실무 카테고리가 꾸준히 쌓이는 것**이다.

## 5. 모든 신규 콘텐츠의 공통 전환 장치

예외 없이 아래 3종을 달고 발행한다. 이것이 "콘텐츠가 문의를 만든다"의 실제 구현이다.

1. **본문 하단 상담 CTA** — `data-consult-source` 로 출처 구분 (어떤 콘텐츠가 문의를 만들었는지 측정 가능해야 함)
2. **회사소개서/교육제안서 다운로드 링크**
3. **관련 도구·가이드 내부 링크** — 체류 시간 및 회유 (도구 → 글 → 다른 도구)

### 발행 전 체크리스트

- [ ] 공통 전환 장치 3종 배치
- [ ] `sitemap.xml` 등재
- [ ] GTM + GA4 스니펫 포함
- [ ] 적절한 JSON-LD (`BlogPosting` / `SoftwareApplication`)
- [ ] 정적 canonical + og:url (JS 주입 아님)
- [ ] 모바일 확인
- [ ] 숫자·로고·보증 문구를 임의로 만들지 않았는지 확인

## 6. 측정

기존 KPI(히어로 CTA 클릭률, 목적별 경로 분포, 가이드 PDF 다운로드율, 상담 CTA 대비 제출 완료율)에 아래를 추가한다.

| 신규 지표 | 측정 방법 | 판단 기준 |
|---|---|---|
| **콘텐츠별 문의 기여** | `submit_contact_form`의 `source_page` 분포 | 어떤 콘텐츠가 실제로 돈이 되는가 |
| 도구별 자연 유입 세션 | GA4 랜딩 페이지 × 자연 검색 | 도구 백로그 우선순위 재조정 근거 |
| 블로그 색인 페이지 수 | Search Console | U1 수정 효과 검증 (4주 후) |
| 네이버 유입 비중 | 네이버 애널리틱스 (설치 후) | U4 착수 여부 판단 |

### 재검토 시점

**2026-10월 말** — 분기 단위로 백로그 우선순위를 재조정한다. 특히 도구 5개 중 실제 유입을 만든 것과 못 만든 것을 구분해, 다음 분기 투자를 유입이 확인된 유형에 집중한다.

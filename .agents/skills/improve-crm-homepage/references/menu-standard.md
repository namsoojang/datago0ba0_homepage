# 데이터공방 메뉴 표준

## 현재 진단 기준일

2026-07-18 작업본 기준으로 일반 페이지는 대체로 `Home, About, Why Us, Curriculum, References, Contact, RPA, Blog`을 사용하지만 다음 차이가 있다.

- 메인과 하위 페이지의 상대경로가 다르다.
- 일부 가이드 페이지는 로고, 시작 가이드, PDF만 제공한다.
- `Guide`가 없는 일반 페이지와 있는 브랜치가 혼재한다.
- 활성 메뉴 표시와 모바일 동작이 페이지별로 달라질 수 있다.
- 메뉴가 8개 이상이라 핵심 전환 CTA가 약해진다.

## 권장 전역 메뉴

| 순서 | 레이블 | 기본 목적지 | 역할 |
|---|---|---|---|
| 로고 | 데이터공방 | `/index.html` | 홈 이동 |
| 1 | 교육·서비스 | `/index.html#curriculum` | 제공 가치 탐색 |
| 2 | 성과·사례 | `/index.html#references` | 신뢰 형성 |
| 3 | 업무도구 | `/rpa.html` | 도구 사용·체험 |
| 4 | 실무가이드 | `/guide/index.html` | 학습·리드마그넷 |
| 5 | 블로그 | `/blog.html` | 전문성·검색 유입 |
| CTA | 교육·협업 문의 | `/index.html#contact` | 상담 전환 |

`About`과 `Why Us`는 홈페이지 본문과 푸터에서 계속 제공하되 전역 메뉴에서는 합치거나 제외하는 것을 우선 검토한다.

## 페이지 전용 보조 메뉴

- 가이드: `가이드 허브, STEP 01 시작, STEP 02 Rules & Skills, PDF`
- 업무도구: `도구 목록, 사용법, 개인정보 처리, 문의`
- 블로그: `전체, 교육 후기, 개발 기록, 실무 자료` 같은 콘텐츠 필터

보조 메뉴는 전역 메뉴를 대체하지 않는다.

## 구현 규칙

- 레이블과 순서를 파일마다 바꾸지 않는다.
- 루트 페이지와 하위 디렉터리의 상대경로만 다르게 계산한다.
- 현재 페이지에는 `aria-current="page"`를 적용한다.
- 주요 CTA는 일반 텍스트 링크와 시각적으로 구분한다.
- 900px 이하에서는 햄버거 메뉴로 전환하되 항목 순서를 유지한다.
- 키보드 포커스, ESC 닫기, 메뉴 버튼의 `aria-expanded`를 확인한다.

## 리팩터링 판단

정적 HTML 파일이 계속 늘어나 메뉴 불일치가 반복되면 다음 중 하나를 별도 작업으로 제안한다.

1. 빌드 단계의 공통 partial
2. 서버 사이드 include
3. 작은 공통 내비게이션 JavaScript

새 의존성을 추가하거나 구조를 바꾸기 전에 사용자 승인을 받는다.

# CRM 홈페이지 점검표와 실행 로드맵

각 항목을 `0 없음`, `1 부분`, `2 명확`으로 평가한다.

| 영역 | 질문 |
|---|---|
| 메뉴 | 모든 페이지에서 전역 메뉴의 이름과 순서가 같은가? |
| 메시지 | 첫 화면에서 대상 고객과 기대 결과를 바로 알 수 있는가? |
| CTA | 주요 행동 하나와 낮은 부담 보조 행동이 구분되는가? |
| 신뢰 | 실제 기관, 사례, 결과물, 검증 과정이 가까이 있는가? |
| 경로 | 교육·도구·가이드·상담의 차이가 방문자 관점에서 보이는가? |
| 콘텐츠 | 문제 → 해결 → 근거 → 다음 행동의 맥락이 이어지는가? |
| 폼 | 필수 필드가 최소이며 수집 목적과 동의가 분명한가? |
| CRM | 관심 분야, 유입 콘텐츠와 상담 의도가 저장되는가? |
| FAQ | 주요 반대 질문과 구매 불안을 해소하는가? |
| 측정 | CTA, PDF, 폼 완료를 구분해 측정하는가? |
| 모바일 | 메뉴, 카드, 폼과 CTA가 작은 화면에서도 자연스러운가? |
| 접근성 | 키보드, 포커스, 레이블, 대비와 상태 안내가 적절한가? |

## 실행 순서

### 1단계: 발견 가능성

- 전역 메뉴 표준화
- Guide와 문의 CTA 노출
- 활성 상태와 모바일 메뉴 정리

### 2단계: 메시지와 신뢰

- Hero 결과 문장 정리
- 고객 문제 3개 작성
- 실제 사례와 신뢰 근거를 첫 화면 가까이 이동

### 3단계: 여정과 전환

- 방문 목적별 서비스 경로
- 가이드 허브와 다음 단계 CTA
- PDF 다운로드와 상담 폼 분리

### 4단계: CRM 품질

- 최소 필드와 관심 분야 라우팅
- 개인정보 동의와 후속 연락 안내
- 문의 유형별 메시지와 담당 처리 기준

### 5단계: 측정과 반복

- GA4 이벤트
- 페이지별 전환율 비교
- 이탈이 큰 단계 한 곳씩 개선

## 한 번의 작업에서 지킬 범위

- 하나의 퍼널 문제를 선택한다.
- 성공 지표를 하나 이상 정한다.
- 관련 없는 디자인 전면 개편을 섞지 않는다.
- 배포 후 다음 개선 후보를 한 가지 제안한다.

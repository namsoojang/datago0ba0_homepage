# Re:catch CRM 홈페이지 벤치마크

분석 기준: [Re:catch 한국어 홈페이지](https://www.recatch.cc/ko), 2026-07-18 확인.

## 관찰한 전환 구조

1. **성과 중심 첫 문장**: 제품 기능보다 `B2B 매출 성장`이라는 결과를 먼저 제시한다.
2. **두 단계 CTA**: 소개서 다운로드 같은 낮은 부담 행동과 도입 문의를 분리한다.
3. **즉시 신뢰 형성**: 첫 화면 다음에 선택 기업과 고객 근거를 배치한다.
4. **문제 언어 사용**: 리드 확보, 전환 불명확, 도구·데이터 비효율을 방문자의 목소리로 설명한다.
5. **문제별 솔루션 분기**: 블로그, 웹사이트, 리드마그넷, AIX, CRM 등 목적별 경로를 제공한다.
6. **구체적인 결과 증거**: 고객 사례에 전환율, 처리 속도, 담당자 역할을 함께 제시한다.
7. **위험 해소**: 보안 인증과 기능을 별도 영역으로 제공한다.
8. **FAQ로 반대 질문 처리**: 적합 고객, 차별점, 도입 기간, 가격과 부적합 사례를 다룬다.
9. **마지막 이중 CTA**: 소개서와 1:1 상담을 다시 제시한다.

## 데이터공방 적용 제안

| Re:catch 패턴 | 데이터공방 적용 | 주의점 |
|---|---|---|
| 성과 중심 Hero | `교육 후 현업 적용`, `반복 업무 자동화`, `검증 가능한 AI 활용` 중 핵심 결과 선택 | 한 화면에 세 메시지를 경쟁시키지 않는다 |
| 낮은 부담 CTA | 실무 가이드, 체크리스트, 사례 보기 | 자료 다운로드를 과도한 폼으로 막지 않는다 |
| 고의도 CTA | 기업 교육·자동화 진단 문의 | 예상 답변 방식이나 다음 단계를 안내한다 |
| 고객 문제 영역 | 교육이 현업으로 이어지지 않음, 반복 업무, AI 결과 검증 어려움 | 실제 고객 인터뷰와 문의 내용을 우선 사용한다 |
| 서비스 분기 | 교육, 자동화 도구, 가이드, 자문 | 기술 명칭보다 고객 상황으로 레이블링한다 |
| 사회적 증거 | 실제 출강 기관, 후기, 교육 사진, 결과물 | 사용 허가와 사실을 확인한다 |
| 사례 카드 | 대상·문제·개입·결과·다음 단계 구조 | 검증되지 않은 성과 수치를 만들지 않는다 |
| FAQ | 교육 대상, 준비물, 커리큘럼 조정, 보안, 비용·일정 | 영업 과정에서 자주 받는 질문을 우선한다 |
| 반복 CTA | 각 여정 끝에 맥락별 CTA | 모든 버튼을 같은 `문의하기`로 쓰지 않는다 |

## 데이터공방 권장 페이지 흐름

```text
성과 약속 + 주요 CTA
→ 실제 기관·사례 근거
→ 고객 문제 3가지
→ 문제별 교육·서비스 경로
→ 대표 사례와 결과
→ 실무 도구·가이드 체험
→ 진행 방식과 안전·검증 원칙
→ FAQ
→ 자료 보기 / 교육·협업 문의
```

## 그대로 모방하지 않을 요소

- 데이터공방 규모에 맞지 않는 대기업형 제품 메뉴
- 검증되지 않은 로고 나열과 대규모 성과 숫자
- 서비스가 많아 보이기 위한 중복 카드
- 방문 목적과 관계없는 긴 보안 인증 영역

핵심 구조만 참고하고 데이터공방의 실제 교육·자동화 사례와 장남수 강사의 검증 원칙으로 재작성한다.
